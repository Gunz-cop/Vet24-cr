# Implementación local I04 / #30

Se implementó una guardia común para Worker y middleware que valida host, configuración, firma RS256/JWKS, issuer, audience, exp, nbf, sub y allowlist. La caché de claves tiene límite, TTL, timeout y cooldown. El Worker transmite únicamente la identidad mínima por contexto de la solicitud; el middleware vuelve a autenticar cuando ese contexto no existe. No hay bypass de localhost ni fixtures en el producto.

Las respuestas administrativas llevan `private, no-store` y `noindex, nofollow`; HEAD no lleva cuerpo y errores de escritura son JSON con requestId. Se rechazan rutas ambiguas, métodos no admitidos y CSRF. El lector de JSON cancela al exceder 64 KiB reales, sin duplicar el stream. Las escrituras administrativas aún no implementadas terminan en 503 antes de delegar al adapter; I05 debe transferir el payload validado al incorporar persistencia y rate store atómico.

Se eliminaron los cuatro handlers de `functions/`. El GET/HEAD público de compatibilidad retorna 503 `LIVE_NOT_READY`, mientras escrituras/OPTIONS retornan 405. Analytics y cron-check-links retornan 410 en todos los métodos. El Worker llama las mismas funciones exportadas por estos endpoints antes del adapter para evitar redirects de slash de Astro; no hay una segunda implementación de la lógica. Se retiró la telemetría del cliente, se excluyó admin del sitemap y sus páginas son dinámicas y provisionales.

El gate inventaría las siete rutas API permitidas, scripts/configuración y artefactos compilados; rechaza nuevas rutas, Functions, autoridad legacy y assets estáticos administrativos. Las pruebas negativas comprueban también el manifiesto del bundle y scripts de despliegue alternativo.

Programación inicial y gate: Luna medium; integración y correcciones finales: agente principal. Auditoría independiente Luna medium: APROBADO en `auditoria-i04-r3.md`, mantenido tras refuerzo de pruebas/gate en `auditoria-i04-r4.md`. El falso positivo de r2 quedó invalidado explícitamente en r3.

La evidencia conjunta está en `verificacion-i01-i04.md`. No se provisionó Access ni se tocó D1 remoto. ADMIN_ENABLED permanece false y los valores Access vacíos. La comprobación de políticas Access y despliegues legacy remotos pertenece a I11; el endurecimiento del reporte público pertenece a I07. No se hizo deploy, commit ni push.
